# AI 半智能体（Human-in-the-Loop）技术方案

> 目标：用 AI 减少「空刷、找入口、错过开售」的时间；  
> **支付 / 人脸 / 验证码由主人亲手完成**；不绕过 App 风控与生物识别。

---

## 1. 产品定义

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| AI 半智能体 | 理解任务、盯开售、打开官方页、走到待确认节点、语音/通知提醒 | 伪造触摸骗过检测、代付、绕过人脸 |
| 主人 | 支付、人脸/指纹、验证码、最终确认 | — |
| 官方 App | 购票/支付的真实业务与安全 | — |

典型话术：

1. 用户：「帮我盯周杰伦上海场，开售提醒我」  
2. AI：到点打开大麦对应页 / 发出强提醒  
3. AI：「主人，已到待支付，请你支付」  
4. 用户完成支付后，AI 确认并归档结果

┌─────────────────────────────────────────────┐

**原则：业务安全在官方 App；系统只让助手更好用。**

## 3. 分阶段落地（强烈建议按序）

### 阶段 1 — 普通 Android App（先验证，不改 AOSP）

**交付物：** 可安装的 Assistant APK  

能力清单：

1. 对话下发任务（购票盯梢 / 开售提醒）  
2. 本地任务库（场次、开售时间、状态）  
3. 准时强通知 + 可选 TTS：「主人，开售了」  
4. Deep Link / 包名拉起官方 App 到尽可能深的页面  
5. 状态机节点：`WATCHING → OPENING → NEED_USER_PAY → DONE / FAILED`  
6. 「需主人确认」卡片：支付、人脸、验证码  

**技术栈建议：**

- Kotlin + Jetpack Compose  
- WorkManager / AlarmManagerExact 做开售闹钟  
- Foreground Service 仅在开售窗口短时使用  
- LLM：云端 API（或后续本地小模型）做意图解析  
- 数据：Room  

### 阶段 2 — AOSP 轻度配合

在阶段 1 跑通后：

| 改造点 | 位置（示意） | 作用 |
|--------|--------------|------|
| 预装助手 | `packages/apps/AiButler/` | 出厂自带 |
| 设为默认 Assistant | RoleManager / config | 长按唤起 |
| 通知渠道高优先级 | Framework / App | 开售不被静音淹没 |
| 白名单保活（克制） | device overlay | 开售窗口不被杀 |

### 阶段 3 — AOSP 中度配合（你提到的第三阶段）

| 改造点 | 作用 |
|--------|------|
| `priv-app` 系统特权 | 更稳的助理权限（仍不代过人脸支付） |
| 定制 Launcher / 助理桌面 | 对话为主，减少图标干扰 |
| 系统级「待确认中心」 | 聚合：请支付 / 请人脸 / 请验证码 |
| 任务切换策略 | 一键把购票 App 拉到前台 |

**明确不做：** Kernel 伪造触摸、对抗风控、自动完成支付。

## 4. 核心模块设计

### 4.1 任务状态机

```
CREATED
  → WATCHING          # 盯开售
  → NOTIFY_OPEN       # 提醒开售
  → LAUNCH_OFFICIAL   # 打开官方 App
  → NEED_USER_ACTION  # 支付/人脸/验证码（阻塞，等主人）
  → VERIFY_RESULT     # 查询或询问是否成功
  → DONE | FAILED | CANCELED
```

`NEED_USER_ACTION` 是产品核心：AI **暂停自动化**，只提醒。

### 4.2 官方调起策略（优先级从高到低）

1. **官方 Deep Link / App Link**（若有公开文档或可稳定复现的 URL）  
2. **显式 Intent**（包名 + Activity，需适配版本变化）  
3. **仅打开 App 首页 + 语音指引主人点哪里**  
4. （可选，弱）无障碍辅助导航——失败则立刻降级为指引，不硬刷  

### 4.3 提醒引擎

- 开售前 T-24h / T-1h / T-5m / T-0  
- 通道：`NotificationChannel(IMPORTANCE_HIGH)` + 全屏意图（类似闹钟，需权限）  
- 文案固定模板：  
  - 「主人，开售了，请打开大麦完成选票」  
  - 「主人，已到支付步骤，请你支付」  
  - 「主人，需要人脸识别，请你配合」  

### 4.4 LLM 职责边界

| LLM 负责 | LLM 不负责 |
|----------|------------|
| 解析「买哪场、谁的票」 | 直接持有支付密码 |
| 生成任务参数与提醒文案 | 决定绕过验证 |
| 总结「你下一步点哪里」 | 控制高频抢票点击 |

工具调用（Tool Calling）示例：

- `createWatchTask(artist, city, saleTime, channel)`  
- `scheduleAlert(taskId, when)`  
- `launchOfficialApp(taskId)`  
- `requestOwnerAction(taskId, PAYMENT | FACE | CAPTCHA)`  
- `markTaskDone(taskId)`

## 5. AOSP 配合清单（阶段 3 最小集）

```
AOSP/
├── packages/apps/AiButler/          # 助手应用（priv-app）
├── packages/apps/AiButlerConfirm/   # （可选）待确认中心 UI
├── device/<vendor>/<product>/
│   └── overlay/.../config.xml       # 默认 assistant 包名
└── frameworks/base/...              # 仅当通知/角色能力不够时再动
```

编译侧：

1. `Android.bp` 将 AiButler 标为 `privileged: true`（按需）  
2. 权限在 `privapp-permissions-*.xml` 白名单声明  
3. `PRODUCT_PACKAGES += AiButler`  

开发机建议：先 **AOSP 模拟器 / Cuttlefish 或 Pixel**，不要一上来适配任意国产机 BSP。

---

## 6. 安全与合规（写进产品红线）

1. 不收集、不代填支付密码  
2. 生物识别只在官方 App 内由系统/银行/平台完成  
3. 不提供「刷穿队列 / 撞接口」类能力  
4. 自动化以 **提醒与拉起官方页面** 为主；高频点击不是目标  
5. 用户协议中明确：助手不能保证抢到票

## 7. 里程碑建议

| 里程碑 | 内容 | 是否要 AOSP |
|--------|------|-------------|
| M1 | 对话建任务 + 本地闹钟提醒 | 否 |
| M2 | 一键拉起大麦/购票 App + 「请支付」卡片 | 否 |
| M3 | 开售全屏提醒 + TTS | 否 |
| M4 | 预装进 AOSP，默认助理 | 轻度 |
| M5 | 助理桌面 + 待确认中心 | 中度 |

---

## 8. 和「无 App 未来」的关系

本方案是过渡态：

**表面：一个 AI 入口**  
**背后：官方 App 做事**  
**关键：人确认**  

这与马斯克式「纯意图、无 App」仍有距离，但是 **当前安全、可做、可演示** 的路径。
